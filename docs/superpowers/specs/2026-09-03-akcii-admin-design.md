# Мини-админка акций для prootdyhspb.ru

Дата: 2026-09-03
Статус: согласован, готов к плану реализации

## Задача

Заказчик («Проотдых», Оксана) должен наполнять раздел «Акции» сам, без обращения к разработчику.
Сейчас каждая акция — два несвязанных куска HTML в `akcii.html`: плитка в сетке и модальное
окно с условиями, связанные якорем. Десять акций, править их руками может только тот, кто
понимает вёрстку.

Решение: акции переезжают в `data/akcii.json`, публичная страница рендерится из него, а
закрытая паролем страница `/upravlenie` даёт формы для правки.

## Что подтверждено на хостинге

Проба `_probe_9f3a.php` от 2026-09-03 (файл с прода удалён):

- PHP `8.3.31`, SAPI `cgi-fcgi`, процесс от пользователя `u3617178`
- DOCUMENT_ROOT `/var/www/u3617178/data/www/prootdyhspb.ru`
- `mkdir`, `file_put_contents`, `file_get_contents`, `unlink`, `rmdir` в каталоге сайта — все успешны
- `json_encode`, `password_hash` доступны
- `session.save_path` = `/tmp/u3617178`

Каталог выше DOCUMENT_ROOT по FTP недоступен (FTP-корень — `/www`), поэтому данные и конфиг
лежат внутри сайта и закрываются правилами Apache.

## Решения, принятые до начала работ

| Вопрос | Решение |
|---|---|
| Рендеринг страницы | `akcii.php` читает JSON при каждом запросе. Один источник правды, рассинхрона быть не может |
| Авторизация | PHP-сессия + `password_hash`, своя форма входа |
| Возможности | CRUD акций, выбор темы и размера плитки, вкл/выкл без удаления, порядок карточек |
| Дата окончания акции | Не делаем. Срок пишется словами в тексте условий, снятие — галкой «показывать» |
| Адрес админки | `/upravlenie` |
| Учётные записи | Одна общая |
| Где ведём разработку | Сразу на хостинге, в каталоге `_dev/` |

## Структура файлов

```
akcii.php                  публичная страница, рендерит из JSON
lib/promos.php             чтение, запись, валидация, транслитерация
lib/render.php             шаблоны плитки и модалки, экранирование
lib/.htaccess              deny from all
data/.htaccess             deny from all
data/akcii.json            акции, единственный источник правды
data/config.php            хеш пароля и секрет сессии; НЕ в git
data/config.sample.php     образец конфига, в git
data/login_attempts.json   счётчик неудачных входов
data/backups/*.json        10 последних версий, откат руками
upravlenie/index.php       вход, список акций, формы
upravlenie/auth.php        сессия, проверка пароля, CSRF, счётчик попыток
upravlenie/actions.php     операции над списком: показ, порядок, удаление
```

`data/` и `lib/` закрыты `deny from all`: JSON секретов не содержит, но конфиг с хешем пароля
лежит рядом, и если PHP на хостинге когда-нибудь отвалится, исходники не должны отдаваться
текстом. По той же причине конфиг лежит в `data/`, а не внутри `upravlenie/`.

## Модель данных

`data/akcii.json` — объект с версией формата и массивом акций. Порядок элементов массива
равен порядку карточек на сайте.

```json
{
  "version": 1,
  "promos": [
    {
      "id": "egypt",
      "enabled": true,
      "badge": "−35%",
      "title": "Египет",
      "note": "Хургада, всё включено",
      "theme": "t-red",
      "big": false,
      "modal_title": "Египет со скидкой −35%",
      "modal_sub": "Хургада и Шарм-эль-Шейх, всё включено, вылеты каждую неделю.",
      "modal_text": "Отели 5★ с собственным пляжем и аквапарком. Скидка действует при бронировании тура от 7 ночей до конца месяца."
    }
  ]
}
```

Поля:

| Поле | Тип | Ограничения | Куда идёт |
|---|---|---|---|
| `id` | строка | `[a-z0-9-]`, 1–40, уникален в файле | якорь `#p-<id>` |
| `enabled` | булево | — | скрытая акция не выводится вообще |
| `badge` | строка | 1–20 символов | `.pt-badge` |
| `title` | строка | 1–60 | `.pt-city` |
| `note` | строка | 0–90 | `.pt-note` |
| `theme` | строка | одно из восьми значений ниже | класс плитки |
| `big` | булево | — | класс `is-big` |
| `modal_title` | строка | 1–90 | `<h3>` модалки |
| `modal_sub` | строка | 0–160 | `.pmodal__sub` |
| `modal_text` | строка | 1–1200, многострочная | `.pmodal__txt` |

Допустимые темы, взяты из `style.css:394-401`: `t-red`, `t-blue`, `t-magenta`, `t-green`,
`t-orange`, `t-cyan`, `t-grad`, `t-grad2`.

`id` задаётся один раз при создании: транслитерация `title` в латиницу, нижний регистр,
пробелы в дефисы, при совпадении добавляется `-2`, `-3`. При редактировании `id` не меняется —
от него зависит якорь `#p-egypt`, а на такие адреса могут вести ссылки из соцсетей. Переименование
акции не должно ломать чужую ссылку.

Кнопка в модалке ведёт на `/#contact` у всех акций — так во всех десяти сейчас, отдельным
полем не делаем.

## Публичная страница

`akcii.php` — это нынешний `akcii.html`, в котором два блока заменены циклами по JSON:
сетка `.pgrid` и группа `.pmodal`. Шапка, hero, CTA-полоса и подвал остаются неизменными.
Внешне страница после переезда не отличается от текущей ни на пиксель — десять акций
переносятся один в один, вместе с темами и размерами плиток.

Экранирование: все поля выводятся через `htmlspecialchars($v, ENT_QUOTES, 'UTF-8')`.
Заказчик пишет живой текст, в нём будут и «кавычки», и `<`, и `&`. `modal_text` дополнительно
проходит `nl2br` — переводы строк в форме должны стать переносами на странице.

Отказоустойчивость: если `data/akcii.json` отсутствует, не читается или не парсится,
страница берёт свежайший файл из `data/backups/`. Если и там пусто — выводится сетка без
акций и текст CTA-полосы, но не белый экран и не PHP-ошибка. `display_errors` на публичной
странице выключен принудительно.

Правило чистых URL в `.htaccess` расширяется так, чтобы `/akcii` отдавал `akcii.php`, а
остальные шесть страниц продолжали резолвиться в `.html`. `akcii.html` после переезда
удаляется — иначе он выиграет у `.php` в порядке проверки и правки не будут видны.

## Админка

Полностью без JavaScript: обычные формы, `POST`, затем redirect на список (POST/Redirect/GET,
чтобы обновление страницы не повторяло действие). Это тот же подход, что и у модалок сайта
на `:target` — ломаться нечему, на телефоне работает так же, как на десктопе.

Экраны:

1. **Вход** — одно поле пароля, оформление в палитре сайта.
2. **Список акций** — карточки в том порядке, в каком они на сайте. У каждой: бейдж, заголовок,
   цветная метка темы, состояние «показывается / скрыта» и кнопки «Вверх», «Вниз»,
   «Скрыть» либо «Показать», «Изменить», «Удалить». Сверху кнопка «Добавить акцию» и ссылка
   «Открыть страницу акций» для проверки результата.
3. **Форма акции** — поля из таблицы модели данных. Тема выбирается из списка с цветной точкой
   у каждого варианта, свободного ввода цвета нет: иначе палитра сайта разъедется. Размер —
   галка «широкая плитка».
4. **Подтверждение удаления** — отдельный экран с названием акции и двумя кнопками. Никакого
   браузерного `confirm`.

### Авторизация

- Пароль хранится как `password_hash(..., PASSWORD_DEFAULT)` в `data/config.php`, проверяется
  `password_verify`. Открытого пароля в файлах нет.
- Сессия: своё имя, cookie с `httponly`, `samesite=Lax`, `secure` (сайт целиком на https),
  идентификатор пересоздаётся после удачного входа.
- После пяти неудачных попыток с одного IP — пауза 15 минут, счётчик в `data/login_attempts.json`.
  Пятая попытка и позже отвечают одинаково вне зависимости от правильности пароля.
  IP берётся из `X-Forwarded-For`: сайт стоит за nginx-прокси рег.ру, в `REMOTE_ADDR` придёт
  адрес прокси, и один счётчик станет общим на всех посетителей. На этом же месте уже обжигались
  с `X-Forwarded-Proto` при настройке https.
- На всех формах, меняющих данные, CSRF-токен из сессии; запрос без совпадающего токена
  отклоняется.
- Каталог `upravlenie/` закрывается от индексации заголовком `X-Robots-Tag: noindex`. Файла
  `robots.txt` на сайте сейчас нет — он создаётся в рамках этой работы, с запретом на
  `/upravlenie`.

Пароль генерируется при установке и передаётся отдельным файлом для `curl --netrc-file`,
не в переписку.

### Запись данных

Сохранение атомарное: JSON пишется во временный файл в том же каталоге и переносится
`rename()` поверх боевого. Обрыв скрипта на середине не оставит обрезанный файл — страница
всегда видит либо старую, либо новую версию целиком.

Перед каждой записью текущая версия копируется в `data/backups/akcii-<метка времени>.json`,
хранятся десять последних, лишние удаляются. Это не бэкап «на всякий случай» — это то, что
придётся возвращать, когда заказчик сотрёт текст акции и захочет его обратно.

Валидация на записи: обязательные поля непусты, длины в пределах из таблицы, `theme` из
белого списка, `enabled` и `big` приводятся к булеву, `id` уникален. Неверные данные
возвращают форму с сообщением и сохранёнными полями, а не пустую форму.

## Порядок работ и проверка

Разработка идёт в `_dev/` на хостинге: боевые файлы не затрагиваются, пока новая страница
не проверена целиком. Заливка — пачкой одной командой `curl`, а не по файлу.

Боевой `.htaccess` правится последним шагом, когда `_dev/` уже работает: ошибка в правилах
переписывания кладёт весь сайт, и делать её нужно тогда, когда всё остальное проверено.

Что проверяется:

- перенос десяти акций не изменил вёрстку — сравнение отрисовки до и после;
- полный цикл: создание, правка, скрытие, показ, перемещение вверх и вниз, удаление;
- вход с неверным паролем, срабатывание паузы после пяти попыток;
- форма с чужим или отсутствующим CSRF-токеном отклоняется;
- поле заголовка с `<script>` и с кавычками выводится на странице текстом, а не кодом;
- повреждённый `data/akcii.json` — страница поднимает бэкап и не показывает ошибку;
- `data/akcii.json`, `data/config.php`, `lib/promos.php` по прямым адресам отдают 403;
- страница акций и админка на ширине 390 px.

## Что в эту работу не входит

- Акции на главной странице — их там нет, блок живёт только на `/akcii`.
- Загрузка изображений: плитки сделаны на градиентах, картинок в них не предусмотрено.
- Правка остальных страниц сайта через админку.
- Несколько учётных записей, роли, журнал действий.
- Восстановление из бэкапа кнопкой в интерфейсе: файлы лежат в `data/backups/`, откат
  делается вручную. Понадобится — добавим отдельно.
